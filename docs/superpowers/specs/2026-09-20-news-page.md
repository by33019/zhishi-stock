# M3-05 前端 `/news` 接入真实资讯接口

> 里程碑：M3-05（P1，依赖 M3-04）｜分支 `main`｜状态：设计（实现后回填 §6 / §8）

## 1. 背景

### 1.1 后端接口现状（本轮的数据源）

M3-04 已交付资讯域，六个端点全部 `PUBLIC`，并已通过真实端到端联调
（明细见 `2026-09-20-news-provider.md` §8.3）：

| 编号 | 端点 | 本轮用途 |
| --- | --- | --- |
| NEWS-01 | `GET /news` | 资讯中心列表（**唯一主数据源**） |
| NEWS-02 | `GET /news/{newsId}` | **本轮不消费**（见 §2.2） |
| NEWS-03 | `GET /news/sync-status` | **本轮不单独调用**：列表响应已带同源的 `dataStatus` / `lastSuccessfulSyncAt`（见 §3.6） |
| NEWS-04 | `GET /news/options` | 受控筛选项（资讯类型 / 来源类型 / 可用时间范围 / 筛选规则文案） |
| STK-10 | `GET /securities/{securityId}/news` | **本轮不消费**（个股页归后续里程碑） |
| SEC-07 | `GET /sectors/{sectorId}/news` | **本轮不消费**（板块页归后续里程碑） |

NEWS-01 响应是**扁平封套**（与 QTE-01 的 `StockRanking` 同形，少一层解引用）：

```
items[] / page / size / total / totalPages / hasNext / lastSuccessfulSyncAt / dataStatus
```

`items[]` 的元素是契约 §4.3 `NewsSummary`：

- `newsId`（重复稿返回**主记录** ID）、`newsType`（`NEWS` / `ANNOUNCEMENT` / `RESEARCH` / `OTHER`）
- `title`、`summary`（**授权范围内**摘要，可能为 `null`）、`sourceName`、`authorName`
- `publishedAt`、`collectedAt`
- `originalUrl`、`originalAccessStatus`（`AVAILABLE` / `UNAVAILABLE` / `UNKNOWN`）
- `relations[]`：只含 `relationStatus = CONFIRMED` 的关联，元素是
  `targetType`（`SECURITY` / `SECTOR` / `MARKET`）、`targetId`（**对外标识**，如 `sim-600519` /
  `sim-bk0025` / `CN`）、`targetCode`、`targetName`、`relationMethod`、`confidenceScore`

`dataStatus` 是全局枚举（住在 `MarketOverview.DataStatus`）。后端**刻意不产出 `STALE`**：
没有陈旧阈值就不编造阈值。

### 1.2 可直接复用的既有代码

- `services/apiClient.ts`：`apiRequest` / `toQueryString`。后者**丢弃** `null` / `undefined` / 空串，
  保留 `false` / `0`——所以「不选类型」只要传 `undefined` 即可，不必拼空串。
- `composables/useRemoteData.ts`：三态（`data` / `loading` / `error`）+ `reload()`，
  含**请求序号守卫**（并发返回顺序不保证）。**刻意不做**缓存 / 去重 / 轮询。
- `pages/RankingsPage.vue`：已有的「服务端筛选 + 真实分页」样板。
- `utils/format.ts` 的 `formatDateTime`：钉 `Asia/Shanghai`，非法值返回 `--`。
- `components/PageHeader.vue`：`data-time` 属性承载数据截止时间。
- `types/domain.ts` 的 `DataStatus`、`PageData<T>`、`ApiResponse<T>`。

## 2. 目标与非目标

### 2.1 目标

1. 新建 `services/newsApi.ts`，接 **NEWS-01 + NEWS-04**。
2. `pages/NewsPage.vue` 改读真实接口：**服务端分页 + 服务端类型筛选 + 服务端关键字搜索**。
3. 类型标签由 NEWS-04 的 `newsTypes` **动态生成**，前端不硬编码可选枚举
   （只保留「枚举值 → 中文名」的显示映射）。
4. 「查看原文」用真实 `originalUrl`，并按 `originalAccessStatus` 决定**是否可点**。
5. `data-time` 展示真实 `lastSuccessfulSyncAt`；`dataStatus` 非 `REALTIME` 时给可读提示。
6. `relations` 渲染为可跳转标签（`SECURITY` → `/stocks/:id`、`SECTOR` → `/sectors/:id`、
   `MARKET` → 纯文本）。
7. 删除 `services/mockApi.ts` 与 `mockApi.test.ts`——M3-05 是它的最后一个消费者。
8. 侧栏两块无数据来源的内容**降级为「尚未实现」**，不保留编造数字。

### 2.2 非目标（写明归属，不在本轮偷偷扩大范围）

## 3. 设计

### 3.1 新增 / 修改文件

| 动作 | 文件 | 说明 |
| --- | --- | --- |
| 新增 | `src/services/newsApi.ts` | `getNews(query)` → NEWS-01；`getNewsOptions()` → NEWS-04 |
| 新增 | `src/pages/NewsPage.test.ts` | 页面行为测试（§4 的约束逐条落成用例） |
| 修改 | `src/pages/NewsPage.vue` | 接真实接口；侧栏降级；原文链接按授权状态渲染 |
| 修改 | `src/types/domain.ts` | 新增 `NewsSummary` / `NewsRelationSummary` / `NewsPage` / `NewsOptions` / `NewsQuery`；`NewsItem` **保留**并加注释说明它与资讯域不同源（见 §3.8） |
| 删除 | `src/services/mockApi.ts` + `mockApi.test.ts` | 最后一个消费者消失 |

### 3.2 筛选全部走服务端，列表只在响应内渲染

原型用 `computed` 做客户端过滤（类型 + 关键字）。改为**每个条件都是请求参数**：

| UI | 参数 | 取值 |
| --- | --- | --- |
| 类型标签「全部」 | 不传 `newsTypes` | —— |
| 类型标签「快讯」 | `newsTypes=NEWS` | 单值 |
| 类型标签「公告」 | `newsTypes=ANNOUNCEMENT` | 单值 |
| 类型标签「研报」 | `newsTypes=RESEARCH` | 单值 |
| 关键字输入框 | `keyword` | 显式提交后的值 |

标签集合 = `['全部'] + options.newsTypes`，**顺序与文案都来自服务端**
（`OTHER` 这类前端没预料到的类型会自动多出一个标签，而不是被静默丢掉）。
中文名映射（`NEWS` → 快讯、`ANNOUNCEMENT` → 公告、`RESEARCH` → 研报、`OTHER` → 其他）
是**显示层**的事，放前端；**未知枚举值回退为原值**，不渲染成空白。

### 3.3 关键字是显式提交，不是输入即搜

输入即搜会让每个按键都发一次请求（并让「最后一次响应」的语义变得依赖打字速度）。
改为：输入框绑定本地 `draftKeyword`，**回车或点击搜索按钮**才把它写进 `keyword` 并触发请求。
这与 M3-03 的「选股面板显式提交」是同一套约定。

### 3.4 分页与请求时序

- 请求参数：`page`（从 1 开始）、`size`（显式传，不依赖后端默认）。
- `hasNext` 决定「下一页」可用性，`total` / `totalPages` 用于「共 N 条」。
- **翻页必须保留当前筛选条件**（类型 + 关键字）——这是最容易漏的一条。
- 切换筛选 / 搜索 / 翻页都走 `useRemoteData.reload()`，由**请求序号守卫**保证
  「先发的慢请求后到达」不会覆盖新结果。

### 3.5 原文链接按授权状态渲染

`originalAccessStatus` 的三种取值对应三种渲染，**绝不用 `href="#"` 占位**
（M2-11 的教训：写死的标识符只要需要被别处解析就是缺陷）：

| 取值 | 渲染 |
| --- | --- |
| `AVAILABLE` | `<a>` 指向 `originalUrl`，新窗口打开，带 `rel=noopener noreferrer` |
| `UNKNOWN` | **同样渲染链接**，并额外标注「（原文状态未知）」 |
| `UNAVAILABLE` | 不可点的文本「原文不可用」 |

**`UNKNOWN` 也给链接**是 e2e 之后改的（初稿里它是纯文本）。契约 §4.3 把两件事分开定义：
`originalUrl` 是「经协议和安全校验的原文地址」，`originalAccessStatus` 描述的是**内容**
可访问性。而模拟源目前**一律**产出 `UNKNOWN`（`NewsIngestionService` 第 150 行硬编码），
所以按初稿的写法，真实环境里「查看原文」会**全部消失**——8 条资讯一个链接都没有。
标注「状态未知」比藏起链接更诚实，也比谎称可访问更诚实。

### 3.6 数据状态与截止时间

- `data-time` = 最近更新 `formatDateTime(lastSuccessfulSyncAt)`。
- `dataStatus` 三态提示：`REALTIME` 不加提示；`DELAYED` → 「数据延迟」；
  `UNAVAILABLE` → 「资讯源暂不可用」。
- **前端不自行降级**：不按「稿件日期不是今天」推断陈旧（已知问题 #19 同源——模拟源按
  最近一个已完成交易日生成稿件，周末必然「看起来旧」，此时 `dataStatus` 仍是 `REALTIME`）。
  也不产出后端没有的 `STALE`。
- **空列表的两种语义要分开**：`dataStatus === 'UNAVAILABLE'` 时说「资讯源暂不可用」；
  否则说「暂无符合条件的资讯」。把「取不到数」写成「没有数据」是编造。

### 3.7 已知问题 #20 的处置（本轮只定前端）

`NewsCountProvider.countSince` 无论资讯源是否可用都只返回有条数的证券，
实现里**没有任何代码路径产生「未知」**——于是「0 条」被写成了 `null`（不知道）。

- **本轮不改后端语义**：M3-05 是前端里程碑，且契约 §12.2 未规定该字段语义。
- **前端处置（本轮定）**：`latestNewsCount === null` 时**不渲染**该字段，
  而不是渲染成「0 条」。沿用 M3-03 已经落地的做法，并补一条回归测试。
- 后端语义的最终决定留到有真实资讯源之后；`TASKS.md` / `PROJECT_STATUS.md` 的 #20 补一句
  「前端处置已定」。

### 3.8 `MarketOverview.news` 为什么不改

MKT-01 的 `news` 字段目前是**单条模拟资讯**（见 `TASKS.md` 的总览页交付详情），
它的前端类型是 `NewsItem`（`relatedSymbols: string[]`），**与 §4.3 的 `NewsSummary`
不是同一个形状**（后者是 `relations[]` 对象数组）。

改它意味着改 MKT-01 的 `componentStatus` 口径（`news` 是其中一个分量），
属于新里程碑而不是「接一个页面的真实接口」。本轮**只核对、不改**，
并把「`MarketOverview.news` 与资讯域不同源」这件事写进已知问题，避免后来者以为两处同源。

`NewsItem` 在本轮**保留**——这是与本节初稿的偏差，原因在实现时才确认：它仍有消费者
（`types/domain.ts` 第 128 / 153 行的 `MarketOverview.news` 声明）。删掉它就得把结构就地内联，
反而让「总览页的资讯从哪来」更不可见。改为在类型定义处写明它属于 MKT-01、与资讯域不同源。
偏差本身记在 §6。

### 3.9 侧栏降级

原型侧栏两块内容没有任何后端来源：

| 原型内容 | 处置 |
| --- | --- |
| 「今日事件密度」286 条 / 72% 进度条 / 「较近 20 个交易日均值高 18%」 | 改为「尚未实现」占位，不留数字 |
| 「高频主题」金融政策 42 / 半导体设备 36 / 算力 29 / 消费复苏 18 | 同上 |

项目最高优先级原则是**口径宁可留空也不编造**——这些数字连模拟源都没有，
留着会让用户以为平台在统计事件密度。

## 4. 一致性约束（逐条写成测试）

1. 首屏只发**一次** NEWS-01 与**一次** NEWS-04。
2. 切换类型标签只发 NEWS-01（带 `newsTypes`），**不重发** NEWS-04。
3. 输入关键字**不发**请求；回车 / 点击搜索后才发，且带 `keyword`。
4. 翻页请求带 `page` 且**保留**当前的 `newsTypes` 与 `keyword`。
5. 「全部」标签对应**不传** `newsTypes`（不是传空串）。
6. `items` 为空且 `dataStatus === 'UNAVAILABLE'` → 文案是「资讯源暂不可用」；
   否则是「暂无符合条件的资讯」。
7. `originalAccessStatus === 'UNAVAILABLE'` 时不渲染 `<a>`，且页面里不出现 `href="#"`；
   `AVAILABLE` 与 `UNKNOWN` 都渲染链接，后者额外标注「原文状态未知」。
8. `relations` 里 `targetType === 'MARKET'` 不渲染链接；`SECURITY` / `SECTOR` 渲染
   `/stocks/:id` / `/sectors/:id` 链接，且**只在 `targetId` 非空时**渲染。
9. 侧栏**不含** `286` / `42` / `72%` 等原型数字，渲染「尚未实现」。
10. `latestNewsCount === null` 时自选导语不渲染该字段（既有行为的回归保护）。
11. 请求失败时渲染 `error.message` 与 `traceId`（`useRemoteData` 已提供）。
12. `formatDateTime` 对非法值返回 `--`（既有工具函数的回归保护）。

### 8.2 红灯记录（真实红灯，不是编译错误）

- 首次落测试后 **18 项全部失败**：页面还在读 `mockApi`，而测试 mock 的是 `newsApi`，
  `getNews` 一次都没被调用。这是断言级红灯。
- 第一次落实现后仍有 **5 项失败**，暴露了一个真实缺陷：
  `useRemoteData` 只在调用 `reload()` 时才发请求，我最初只给列表调了 `reload()`，
  于是 **NEWS-04 一次都没被请求**，类型标签只剩「全部」。修法是给筛选项也显式
  `reloadOptions()`（`RankingsPage.vue` 里两个 `useRemoteData` 都是这么用的，我漏了）。
- 另有一个**编译级**问题（不算红灯）：类型 `NewsPage` 与组件 `NewsPage` 同名，
  测试里必须 `import type { NewsPage as NewsFeed }`。

### 8.4 e2e 查出的问题

**① `originalAccessStatus` 一律是 `UNKNOWN`，导致「查看原文」全部消失（本轮已修）**

`NewsIngestionService` 第 150 行把 `original_access_status` 硬编码为 `UNKNOWN`（模拟源没有真实原文）。
初稿规则是「只有 `AVAILABLE` 才渲染链接」，于是真实环境下 8 条资讯**一个链接都没有**——
原型里的外链功能完全不可见。

按契约 §4.3 分开理解：`originalUrl` 是「经协议和安全校验的原文地址」，`originalAccessStatus`
描述的是**内容**可访问性。因此改为：`UNAVAILABLE` 不给链接；`AVAILABLE` 与 `UNKNOWN` 都给链接，
后者额外标注「（原文状态未知）」。改完复验：8 条全部有链接。

**② `NewsTimeRange` 把 `isEmpty()` 泄漏成响应里的 `empty` 字段（本轮只记录）**

`GET /news/options` 的 `availableTimeRange` 实测返回
`{"startAt":"...","endAt":"...","empty":false}`——契约 §4.3 只列了 `startAt` / `endAt`。
原因是 `NewsTimeRange.isEmpty()` 是**无参** `isXxx()` 方法，Jackson 按 getter 规则把它序列化了
（同模块的 `Sector.isType(SectorType)` 与 `LoginAttemptState.isLocked(Instant)` 都带参数，不受影响）。

修法是加 `@JsonIgnore`（一行）。**本轮不改**：M3-05 是前端里程碑，前端类型不认这个字段、
功能无影响；记入 `PROJECT_STATUS.md` 已知问题 #21。

### 8.5 e2e 顺带确认（与设计一致，无需改动）

- 游客访问 `/news` 时控制台有一个 401，来自布局的会话探测（不是资讯接口）——既有行为。
- 关键字「银行」返回 0 条：库里那 8 条资讯确实没有匹配项。它证明的是**搜索走了服务端**
  （请求带 `keyword=银行`），不是缺陷。

  前端**不按日期自行降级**。
